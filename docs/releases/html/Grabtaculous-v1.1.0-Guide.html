1. What Grabtaculous Does (In Plain English)

Once grabman v1.0.0 scaffolds your site or stack, Grabtaculous is the server-side engine that actually launches, protects, updates, and rescues it on your VPS—without opening public admin ports that hackers scan for.

1. Stealth Private Control Channel The supervisor daemon (grabtaculousd) only listens on private localhost (127.0.0.1:9440) or a local Unix socket. It actively refuses to bind to public 0.0.0.0, so no management panel is ever exposed on the open internet. Your desktop Gashboard UI connects later through an encrypted SSH tunnel.
2. Locked-Down Read-Only Apps Every generated Docker Compose stack uses read-only root filesystems, drops all Linux capabilities, disables privilege escalation, runs under non-root user 65532:65532, pins exact @sha256: digests (no mutable :latest tags), and binds app/DB ports only to 127.0.0.1.
3. Curated 1-Click App Marketplace Deploy tested, cryptographically verified templates for the full GrabLab CMS + Grex Theme Builder + Groxy AI stack, standalone Grisp apps, private Postgres/MariaDB/Redis stores, analytics, S3 storage, automation, or webmail.
4. Zero-Downtime Updates & Safety Net Before any code or config changes go live, Grabtaculous checks grabman.lock, validates Site DNA, checks your .grab syntax, takes an immutable SHA-256 snapshot, runs database migrations, swaps healthy workers only when /_ready returns HTTP 200, and auto-rolls back if anything breaks.

2. 5-Minute Quick Start Commands

Grabtaculous ships as a single self-contained binary with the curated catalog already built inside it (zero external runtime dependencies).

# 1. Browse curated 1-click blueprints
grabtaculous catalog list
grabtaculous catalog inspect grablab-grex-bundle

# 2. Deploy a hardened --read-only stack + Caddy automatic HTTPS edge config
grabtaculous deploy grablab-grex-bundle --dir ./my-site --domain shop.example.com --edge-proxy caddy

# 3. Audit any Compose file for read-only, non-root, digest pinning, and zero-secret rules
grabtaculous audit --dir ./my-site --require-digest

# 4. Run a 6-stage zero-downtime rollout with pre-flight + migration + snapshot safety
grabtaculous rollout --dir ./my-site --entry src/app.grab --migrate-file migrations/001_init.grab

# 5. Verify snapshots or roll back cleanly in one command
grabtaculous snapshot list --dir ./my-site
grabtaculous snapshot verify <deploy-id> --dir ./my-site
grabtaculous rollback <deploy-id> --dir ./my-site

# 6. Start the stealth loopback supervisor daemon for local/SSH-tunneled control
grabtaculous daemon --listen 127.0.0.1:9440 --state-dir ./.grabtaculous

5. How Zero-Downtime Rollouts & Snapshot Rollbacks Protect You

Fail-Closed Safety Guarantee: Live visitor connections are never cut over to broken code. If grabman solve --verify, grabman dna validate, grab check, or container security auditing fails, Grabtaculous stops in Stage 1 without changing a single live file.
  1. Stage 1 — Preflight: Verifies lockfile hashes via grabman solve --verify, validates Site DNA via grabman dna validate, compiles your .grab entry cleanly with grab check, and audits Compose/secret hygiene.
  2. Stage 2 — Pre-Deploy Snapshot: Saves a SHA-256 manifest (snapshot.json) archiving grabman.lock, Compose/Caddy/Nginx configs, src/, views/, theme/, public/, storage/site-dna.json, and optional DB checkpoints.
  3. Stage 3 — Explicit Migration: Runs idempotent grab migrate --allow-db <alias>:migrate before shifting live traffic (ADR-024f).
  4. Stage 4 — Rolling Grisp Worker Swap: Starts new workers, polls /_ready until HTTP 200 + asset parity pass, switches the proxy upstream, and gently drains old workers over a 30-second window.
  5. Stage 5 & 6 — Post-Cutover Smoke & Auto-Rollback: Confirms live smoke URLs return healthy responses. On any mismatch, automatically restores every file byte-for-byte from the pre-deploy snapshot (GRABTAC-E701 guarantees tamper checks before restore).
